## 一、选题背景与研究意义

### 1.1 研究背景

随着教育数字化战略推进，网络课程、电子教材等已成为高校学习的重要载体，《中国教育现代化 2035》和《教育信息化 2.0 行动计划》均强调信息技术与教育教学深度融合。学生接触的知识分散在课件、讲义、视频与网络资料中，如何将碎片整理成结构清晰、可检索、可复习的个人知识体系，是数字化学习亟待解决的问题。

笔记工具是知识整理的主要入口，但现有工具普遍“重记录、轻结构”：文档式软件按文件夹或时间组织内容，课程层级易在多次增删改后丢失；标签只能平面分类，难以表达“前置知识”“相关概念”等语义联系；双向链接与图谱虽能缓解关联缺失，却常把目录层级与语义关联混在同一张图中。对按课程复习的学生而言，工具应同时回答：知识点属于哪门课、位于哪一层、与哪些知识点存在何种联系。

与此同时，个人知识管理工具正向“本地优先”回归。云端笔记存在隐私与离线可用性顾虑，Electron 方案则体积与内存开销较大；Tauri 2 以 Rust 为后端、复用系统 WebView，具有安装包小、启动快、权限粒度细、数据本地保存等优势。基于此，本课题拟实现一个面向课程学习的知识点笔记与知识图谱联动桌面应用。

### 1.2 研究意义

理论意义上，本课题将概念图与有意义学习理论中的“概念—关系—结构”思想落实到软件模型与交互过程，探索“课程—知识点—笔记”三层组织模型和层级关系与语义关系分离的双关系建模方法；同时研究不依赖云端大模型的本地关联建议，以多源文本特征与可解释理由支持“人在回路”的知识关联构建。

实践意义上，该应用把课程知识点、笔记与关联集中于一个离线工具，形成“记录—组织—关联—可视化—检索”闭环，减少多软件切换成本；其技术架构、迁移方案与自动保存机制对同类工具具有可复用性，单文件数据库也便于备份与迁移。

## 二、国内外研究现状

### 2.1 知识管理与笔记工具现状

国外知识管理工具经历了从文档管理到网络化组织的演进：Evernote、OneNote 以文档和笔记本为核心；Obsidian 以本地 Markdown 为基础，通过双向链接与图谱连接笔记；Roam Research、Logseq 引入块级引用与大纲编辑；Notion、RemNote 则分别以数据库块和概念图、间隔重复见长。国内语雀、飞书文档、幕布等更面向协作或通用记录，专门围绕课程知识点组织与语义关联的工具较少。

总体来看，双向链接与图谱已成为重要方向，但多数工具要求用户手工维护链接，缺少“发现潜在关联”的能力；图谱混合展示目录与链接关系，笔记增长后容易布局混乱；插件化配置也提高了普通学生的使用门槛。

### 2.2 知识图谱与概念图研究现状

概念图由 Novak 基于 Ausubel 的有意义学习理论提出，以节点表示概念、带标签连线表示关系，强调层级组织与交叉连接，已广泛用于教学设计与评价。思维导图从中心主题向外发散，适合梳理思路，但关系表达能力弱于概念图。知识图谱以“头实体—关系—尾实体”三元组描述事实，在语义搜索、推荐与问答中应用广泛；教育知识图谱则被用于知识点建模、学习路径推荐与认知诊断。

然而，现有教育知识图谱多由专家人工构建，或依赖大规模语料与算法抽取，构建成本高、更新周期长，难以适应个人学习中知识结构频繁调整的特点。面向个人学习者的轻量级图谱工具，需要在结构严谨与维护成本低之间取得平衡。

### 2.3 桌面应用与本地优先架构现状

Electron 通过捆绑 Chromium 与 Node.js 获得成熟的跨平台能力，但体积与内存开销较大；Tauri 2 以 Rust 编写后端、调用系统 WebView 渲染前端，安装包通常只有几十兆，并通过 capabilities 对原生能力细粒度授权。数据层常用 SQLite，其单文件、零配置、支持事务与外键的特点适合个人知识管理；Vue Flow 则提供 Vue 3 下的节点—边渲染、缩放平移与布局扩展，可满足中等规模图谱的交互需求。

Tauri 生态仍在演进，部分原生能力需自行封装；中文分词、相似度计算与图谱布局也需组合开源库实现，这些既是难点，也是本课题的实践价值所在。

### 2.4 现有不足与本课题切入点

现有产品存在三点不足：课程层级、笔记内容与语义关联分散在不同工具或视图中，缺少统一的三层模型；知识点关联靠手工建立，缺少低成本、可解释的发现机制；图谱混合层级与语义关系，且与笔记编辑割裂。据此，本课题切入点为：建立三层模型并分离两类关系；设计本地可解释的关联建议；实现笔记与图谱双向联动。

## 三、研究目标与研究内容

### 3.1 研究目标

本课题拟实现一个面向 Windows 平台的本地知识管理桌面应用：以课程为顶层，多级知识点构成课程结构，Markdown 笔记承载内容，标签提供横向分类，语义关联构建知识网络，最终以交互式知识图谱呈现课程知识全貌；数据保存在本地 SQLite，不依赖网络与云端。

具体目标包括：完成五类实体管理，打通“课程—知识点—笔记”链路；实现 Markdown 编辑、预览、自动保存与导入导出；实现关联管理及带理由的本地关联建议；实现可缩放、可拖拽、可筛选的知识图谱并与笔记、知识点页联动；完成首页统计、全局搜索、备份恢复与打包。性能上，期望在约 50 门课程、5000 个知识点、10000 条笔记规模下列表与搜索响应低于 500 ms，500 节点图谱流畅交互，冷启动约 3 s。

### 3.2 研究内容

**（1）领域模型与数据库设计。** 设计课程、知识点、笔记、标签、笔记标签关联、知识点关联六张核心表及关联建议表。知识点通过自引用的 `parent_id` 表达多级目录，通过 `knowledge_relations` 表达语义关系；合理设置主外键、唯一与检查约束、级联删除；采用 UUID 主键与 ISO 8601 时间；数据库变更通过新增迁移文件完成。

**（2）课程与知识点层次管理。** 实现课程增删改查与同名校验；实现知识点多级树、面包屑与详情统计；支持新建子知识点、编辑、删除子树、降为子级、提升一级、修改父节点，以及连同子树迁移课程，并在删除时给出级联数量。

**（3）Markdown 笔记模块。** 实现编辑、分屏、预览三种模式，使用 markdown-it 渲染并禁用内联 HTML；实现防抖自动保存、手动保存、状态反馈与失败重试；支持导入本地 Markdown、导出为 `.md`，并处理标题提取、同名覆盖、大小与编码限制。

**（4）标签与检索。** 实现标签创建、重命名、删除、搜索与同名复用；建立笔记与标签的多对多关联；实现按标题与正文的关键词检索及标签组合筛选，并通过路由参数支持从标签页深链进入笔记库。

**（5）知识点关联与关联建议（重点）。** 实现关联增删改查，支持前置、相关、包含、对比等类型及描述；在数据库与应用层双重防止自关联与重复；关联随知识点删除级联清理。关联建议研究候选生成、特征提取、相似度计算、理由生成及接受、拒绝、忽略机制。

**（6）知识图谱可视化（重点）。** 将知识点映射为节点，将层级关系与语义关联映射为两类边；实现节点拖拽、画布缩放平移、点击查看详情；支持按课程、层级深度、关联类型筛选；提供层次与关系网络布局切换；实现与笔记、知识点页的跳转联动与刷新。

**（7）辅助功能与工程化。** 实现首页统计与最近编辑、全局搜索、应用设置、备份恢复；完成测试、性能优化、图标与版本配置，产出安装包与文档。

### 3.3 拟解决的关键问题

第一，层级关系与语义关系的统一建模与可视化区分：两类关系在数据上独立，在图谱中需同时呈现，必须通过边样式、图例与布局策略避免混淆。第二，本地关联建议的效果与可解释性平衡：中文名称与描述较短、词面重叠稀疏，单一指标不稳定，需要多源特征融合并给出可理解的理由。第三，图谱在层次约束与语义边交叉之间的可读性。第四，自动保存与数据一致性，尤其是切换知识点、关闭窗口、导入覆盖时避免内容丢失或写入已删除数据。

## 四、技术路线与实施方案

### 4.1 总体架构

系统采用前后端分离的单体桌面架构。表现层基于 Vue 3 与 TypeScript，Vue Router 管理路由，Pinia 管理课程、知识点、笔记、标签、主题与布局状态；逻辑层由 Rust 编写，按 `commands`、`models`、`db` 组织，通过 Tauri 命令暴露接口；数据层使用 SQLite，由 rusqlite 访问并开启外键。前端以统一 `invoke` 封装调用并转换错误；Markdown 读写由 Rust 完成，仅用对话框插件选路径。

### 4.2 技术选型

| 层次 | 选型 | 主要理由 |
| --- | --- | --- |
| 桌面框架 | Tauri 2 | 安装包小、内存占用低、权限可控、数据本地化 |
| 前端 | Vue 3 + TypeScript | 组合式 API 便于组织复杂工作区，类型系统降低接口错误 |
| 状态与路由 | Pinia + Vue Router | 轻量、集成度高，支持路由元信息驱动导航 |
| 后端 | Rust | 内存安全、性能稳定，适合文本处理与文件读写 |
| 数据库 | SQLite + rusqlite | 嵌入式、单文件、支持事务与外键，便于备份迁移 |
| Markdown | markdown-it | 解析规则完整、可配置，社区成熟 |
| 图谱 | Vue Flow | 支持 Vue 3、节点边自定义、缩放平移与布局扩展 |
| 文本处理 | jieba-rs 等 | 本地中文分词，满足离线关联建议需求 |

### 4.3 数据库设计

核心表包括：`courses` 保存课程名称、描述与时间；`knowledge_points` 通过 `course_id` 归属课程、通过 `parent_id` 自引用形成多级结构，并建立索引；`notes` 通过 `knowledge_point_id` 归属知识点，保存标题与正文；`tags` 与 `note_tags` 构成标签多对多；`knowledge_relations` 以 `source_id`、`target_id`、`relation_type`、`description` 描述语义关系，通过 `CHECK` 与 `UNIQUE` 约束阻止自关联和重复关联，外键均级联删除。

阶段六将新增 `relation_suggestions` 表，保存候选知识点对、得分、理由、状态与生成时间，并对知识点对建立唯一约束，避免反复推荐；同时考虑新增 `relation_types` 字典表，维护类型名称、颜色与是否有向，使图谱边样式由数据驱动。所有变更以新迁移文件追加。

### 4.4 关键功能实现方案

**（1）关联管理与一致性。** 关联创建在事务中完成，先校验两端知识点存在、不相同、类型合法，再写入记录；重复关联由唯一约束兜底并转换为友好提示；删除知识点时依赖外键级联清理关联与建议；关联类型以枚举或字典表约束，图谱按类型着色并显示关系标签。

**（2）关联建议。** 候选默认为同一课程内的知识点对。文本表示上对标题赋予较高权重、描述次之、关联笔记的标题与正文截断后作为补充；使用 jieba-rs 分词，去除停用词、单字与纯符号，保留中英文术语。相似度以 TF-IDF 加权的余弦相似度为主、词面 Jaccard 系数为辅，综合得分按 `S = 0.45·sim_title + 0.25·sim_desc + 0.20·sim_note + 0.10·jaccard` 计算，超过阈值后取 Top-K 生成候选。推荐理由由共同关键词、主要贡献字段与相似度区间组成，例如“标题与笔记中共同出现：梯度下降、损失函数”。用户接受后写入正式关联，拒绝后记录状态并在一段时间内不再推荐。权重为初始值，将以小规模标注按 Precision@5 评估调整；知识点较多时用候选限制与倒排索引降低计算量。

**（3）知识图谱。** 前端将知识点与关联转换为 Vue Flow 的 `nodes` 与 `edges`：层级边由 `parent_id` 生成，语义边由关联记录生成，两类边使用不同线型、颜色与图例。布局提供层次布局（按父子关系分层）与力导向布局（突出语义连接）。交互包括节点拖拽、画布缩放平移、点击打开详情、双击跳转笔记或知识点页；支持按课程、层级深度与关联类型筛选；刷新时按节点 ID 增量更新并保留手动位置。

**（4）自动保存与数据安全。** 笔记编辑采用 800 ms 防抖保存，保存请求串行排队，避免并发覆盖；切换知识点与关闭窗口前强制落盘；保存失败时保留草稿并提供重试；若当前知识点已被删除，则清理失效状态，禁止把草稿写回不存在的数据。数据库备份通过复制 SQLite 文件或导出 SQL 完成，恢复前校验完整性并提示覆盖风险。

## 五、可行性分析

**技术可行性。** 课题已完成环境搭建、数据库设计与前五个功能模块的原型，验证了 Tauri 2、Vue 3、Rust、SQLite 与 Markdown 渲染路线；课程、知识点、笔记、标签的增删改查、层级调整、自动保存与文件导入导出均已可运行。剩余模块所需技术均有成熟开源方案：jieba-rs 提供本地中文分词，TF-IDF 与余弦相似度为经典方法，Vue Flow 已支持自定义节点、边与布局扩展。

**数据可行性。** 应用数据由用户在学习中自然产生，不依赖外部语料或商业数据集；关联建议的效果评估可采用自建小规模标注集，由若干名同学对候选对进行相关性判断，成本可控。

**经济可行性。** 技术栈均为开源软件，开发与运行不需要服务器、数据库授权或云服务费用；应用打包后可离线使用，维护成本较低。

**风险与对策。** 中文短文本相似度易受分词精度与表述差异影响，拟采用多源特征融合、同义词词典，并通过用户反馈调权；图谱规模增大后可能卡顿，拟采用层级限制、视口裁剪与增量更新；不同 Windows 版本的 WebView 可能存在差异，拟以 Windows 10/11 为主要验证环境；开发周期紧张时按模块优先级迭代，确保核心链路先完成。

## 六、预期成果与创新点

### 6.1 预期成果

1. 一套可安装运行的 Windows 桌面应用，覆盖课程、知识点、笔记、标签、关联、图谱、统计、搜索与备份恢复等功能。
2. 项目源码、数据库迁移脚本、命令接口说明、使用文档与测试用例。
3. 一篇符合本科毕业设计规范的毕业论文，阐述需求分析、总体设计、关键算法、实现与测试过程。
4. 应用安装包与演示材料，用于答辩展示。

### 6.2 创新点

1. **三层组织与双关系建模。** 以“课程—知识点—笔记”组织学习内容，将 `parent_id` 表达的层级关系与 `knowledge_relations` 表达的语义关系分离，并在图谱中以不同边样式呈现，避免目录结构与知识关联相互混淆。
2. **本地可解释的关联建议。** 不依赖云端大模型，融合知识点标题、描述与笔记正文的多源文本特征生成候选，并给出共同关键词等理由；用户可接受、拒绝或忽略，形成“系统建议、用户确认”的人在回路机制，兼顾隐私、成本与可解释性。
3. **笔记与图谱双向联动。** 笔记工作区展示相关知识点并可跳转，图谱中点击节点可查看详情并进入对应笔记，使知识组织与内容编写在同一工具内闭环。
4. **本地优先的轻量架构实践。** 基于 Tauri 2 与 SQLite 构建离线可用的桌面应用，数据以单文件保存，安装包与资源占用低于传统 Electron 方案，为个人知识管理工具提供可复用的工程方案。
