## 一、当前算法的准确事实（评测前提）

下表是代码的实际行为，不是设计意图。写论文、答辩、做评测都以它为准。

| 维度 | 实际实现 | 代码位置 |
| --- | --- | --- |
| 中文切分 | 连续汉字串上取 **二元字组**（2-gram），跳过含常见虚词的二元组，去中文停用词 | `relation.rs:601-649` |
| 英文切分 | 连续 ASCII 字母数字串（允许 `-` `_`），长度 ≥ 2，去英文停用词 | `relation.rs:616-629` |
| 词向量权重 | **词频（TF）**，没有任何 IDF / 文档频率统计 | `relation.rs:655-661` |
| 名称相似度 | 名称字段内词频向量余弦 | `relation.rs:775` |
| 描述相似度 | 描述字段内词频向量余弦 | `relation.rs:776` |
| 笔记相似度 | 笔记字段内词频向量余弦，每知识点笔记截断 3000 字 | `relation.rs:777`、`:20`、`:871-912` |
| 词面重合 | 三字段合并后词集合的 Jaccard | `relation.rs:778`、`:716-732` |
| 融合公式 | `0.45·名称 + 0.25·描述 + 0.20·笔记 + 0.10·Jaccard`，保留 4 位小数 | `relation.rs:780-783`、`:764-766` |
| 入候选阈值 | `MIN_SUGGESTION_SCORE = 0.02`（极低，实际上几乎不过滤，只挡全零向量） | `relation.rs:16`、`:1098` |
| 候选池 | 同课程全部知识点，排除自身、已有关联、已处理（accepted / rejected） | `relation.rs:1070`、`:1076-1087` |
| 排序与截断 | 分数降序、同分按 id 升序保证确定性；默认 Top-8，上限 20 | `relation.rs:1068`、`:1103-1110` |
| 推荐理由 | 名称 / 描述 / 笔记各自的前 3 个共同词，无共同词时给"某字段文本存在综合重合" | `relation.rs:785-813`、`:735-762` |
| 持久化 | 每次生成先删除该知识点全部 pending，再整体重插；知识点对做无序 canonical 化 | `relation.rs:1117-1150` |
| 用户反馈 | `pending / accepted / rejected`，**拒绝即永久排除，没有冷却期** | `relation.rs:954`、`:1199-1210` |
| 计算复杂度 | 每个目标点与同课程全部候选逐一计算，**无倒排索引剪枝** | `relation.rs:1084-1101` |

**两个必须先承认的弱点**（不是缺陷，但要在论文"局限"里写出来）：

1.  2-gram 理由会出现碎片词，例如「梯度下降」可能产出 `梯度`、`度下`、`下降` 三个词，其中 `度下` 对人没有解释力。理由质量需要人工评估，不能默认"有理由 = 可解释"。
2.  阈值 0.02 只起下限作用，实际"是否推荐"由 Top-K 截断决定，不是由阈值决定。论文里不要写"超过阈值后取 Top-K"这种模糊表述，要写成"固定返回 Top-K，阈值仅作全零下限"。

## 二、评测要回答的三个问题

| 编号 | 问题 | 对应的论文论点 |
| --- | --- | --- |
| RQ1 | 融合方案是否优于任一单字段基线？ | 创新点 2「多源文本特征融合」是否成立 |
| RQ2 | 笔记特征（0.20）是否带来可测增益？ | 权重 0.45/0.25/0.20/0.10 有没有依据 |
| RQ3 | 推荐理由是否真的可解释？ | 创新点 2「可解释」是否成立 |

RQ2 是重点：如果笔记特征没有增益，那"融合笔记正文"这个卖点就站不住，需要如实降级为"多字段融合"；如果增益明显，这就是论文最硬的一张表。

## 三、数据与标注

### 3.1 规模（一个人两天内可完成）

-   选 **3 门课程**（尽量不同学科，例如数学类、编程类、文科类），每门课 8–10 个知识点。
-   每个知识点取其 Top-8 候选 → 每门课约 64–80 对，总计 **200–240 对**。
-   去重：知识点对有方向性，必须按无序对去重（A→B 与 B→A 只保留一条），否则同一对被重复标注，指标虚高。

### 3.2 标注等级（三档，不用二值）

| 等级 | 含义 | 例子 |
| --- | --- | --- |
| 2 | 明确应当建立关系 | 「梯度下降」—「学习率」（相关/前置） |
| 1 | 弱相关，连上也说得过去 | 「梯度下降」—「损失函数」描述里只提了一句 |
| 0 | 无关，纯词面巧合 | 「线性回归」—「线性表」 |

三档才能算 NDCG；只标 0/1 会让"排在 3 位的强相关"和"排在 3 位的弱相关"无法区分。

### 3.3 标注流程

1.  两位标注者**独立盲标**，只看到知识点标题、描述、笔记摘录，**看不到算法分数与排序**。
2.  先各标 30 对算 Cohen's κ，κ ≥ 0.6 才开始正式标注；低于 0.6 说明相关性定义有歧义，先修定义。
3.  分歧对由第三人裁决，或直接降级为 1（保守处理）。

### 3.4 必须避开的两个偏差

-   **不要把 `knowledge_relations` 里的已有手工关联当正样本**。算法本身排除了已有关联，用它们做正例会人为压低 P@5，结论不可信。
-   若要同时报召回率，用一份**清空 `knowledge_relations` 的数据库副本**跑算法，再看它能否重新发现历史上的手工关联；这与上面的人工标注评测是两套实验，不要混在一张表里。

## 四、指标

| 指标 | 定义 | 说明 |
| --- | --- | --- |
| P@5 | 前 5 条中 `rel ≥ 1` 的比例 | 主指标，最贴近用户实际看到的条数 |
| P@8 | 前 8 条同上 | 对应默认返回条数 |
| NDCG@5 | `(2^rel − 1) / log2(i + 1)` 归一化 | 衡量排序质量，体现强弱相关的位置 |
| 覆盖率 | 至少返回 1 条候选的目标点占比 | 反映"冷启动 / 无笔记"时的可用性 |
| 理由支持率 | 标注者认为理由能支撑该判断的对数占比 | 回答 RQ3，同时统计 2-gram 碎片词出现频率 |

所有指标按课程分别报，再报宏平均；只报总体平均会掩盖某一门课的灾难性表现。

## 五、基线与消融

### 5.1 基线（同一候选池、同一 Top-5 截断）

| 编号 | 方案 | 作用 |
| --- | --- | --- |
| B0 | 随机（固定种子，同课程随机取 5 个） | 下限，证明任务本身不是随便排都有分 |
| B1 | 仅 Jaccard（三字段合并） | 检验"余弦是否必要" |
| B2 | 仅名称余弦 | 最省事的基线，必须打赢 |
| B3 | 名称 0.6 + 描述 0.4 | 无笔记字段的强基线 |
| B4 | 现方案（0.45/0.25/0.20/0.10） | 待验证方案 |

### 5.2 消融

| 编号 | 改动 | 回答 |
| --- | --- | --- |
| A1 | B4 去掉笔记项，权重按比例回填（0.5625/0.3125/0.125） | RQ2：笔记值不值 0.20 |
| A2 | B4 去掉 Jaccard（0.45→0.50、0.25→0.28、0.20→0.22） | Jaccard 是否只是重复计算 |
| A3 | B4 等权（四项各 0.25） | 当前权重是否优于拍平 |
| A4 | 只把笔记权重从 0.20 提到 0.35，其余等比缩小 | 笔记特征是否被低估 |

A1 与 A3 是本实验的核心价值：它们把"0.45/0.25/0.20/0.10"从"我定的"变成"测出来的"。

## 六、落地方式（不改动生产代码）

`score_candidate` 与 `tokenize` 都是纯函数，不需要数据库，因此可以完全离线跑：

1.  在 `src-tauri/src/commands/relation.rs` 的 `#[cfg(test)] mod tests` 之外新增一个 `#[cfg(test)] mod eval`，函数上加 `#[ignore]`，这样 `cargo test` 不会执行它。
2.  语料放 `src-tauri/tests/fixtures/eval_corpus.json`，字段：`course_id`、`point_id`、`title`、`description`、`notes`；标注结果放 `eval_labels.csv`（`left_id,right_id,rel,labeler`）。
3.  该测试遍历语料、对每个方案重算排序，输出 CSV 到 `src-tauri/target/eval/`。
4.  运行：`cargo test --manifest-path src-tauri/Cargo.toml eval -- --ignored --nocapture`。
5.  指标用 Python 脚本（`scripts/eval_metrics.py`）算，几十行即可；脚本入库，论文附录贴关键片段。

不要为了评测给生产代码加开关参数——评测是独立模块，生产路径保持现状。

## 九、如果要保留 TF-IDF 口径（可选，半天）

两种做法，选其一：

-   **课程级 IDF**：把同一门课的全部知识点文本当语料，`idf(t) = ln((N + 1) / (df(t) + 1)) + 1`，`N` 为课程内知识点数。代价是：每新增一个知识点，全课程向量都会变，需要重算，且不同课程的分数量纲不一致。
-   **不叫 TF-IDF，叫加权词频**：保留 `title/desc/notes` 分字段加权，把"IDF"这个承诺撤掉。**推荐这一条**，改动量最小且诚实。

## 十、论文可直接替换的三段文字

**（1）创新点 2 改写**

> 提出一种不依赖分词模型与云端服务的本地关联建议方法：将中文连续文本切分为二元字组，按标题、描述、笔记三个字段分别构造词频向量，以字段内余弦相似度与全字段 Jaccard 系数加权融合生成候选，并由共同词自动生成推荐理由。方法无需额外模型文件与词典，离线可用、结果确定、理由可回溯；用户可通过接受 / 拒绝参与筛选，被拒绝的知识点对不再重复推荐。实验表明该方法在 Precision@5 上优于单字段基线（见第 X 章）。

**（2）为什么不用 jieba（放在方法章"设计取舍"）**

> 通用中文分词依赖较大词典与模型文件，且对"梯度下降""栈溢出"这类课程术语的切分结果并不稳定；本应用以零依赖、完全离线、结果可复现为设计目标，故采用二元字组切分。其代价是会产生少量无解释力的碎片词（如"度下"），本文通过限制共同词数量并按两端词频排序来缓解，并在实验中单独统计理由支持率。

**（3）局限（必须写，写清楚反而加分）**

> 本方法的相似度计算仅使用词频，未引入逆文档频率，对高频通用词的区分能力有限；候选池限定在同一课程内，跨课程关联依赖人工建立；拒绝状态为永久记忆，缺少时效性衰减；图谱与建议均未在超过 500 个节点的规模下做压力测试。

## 十一、不建议做的事

-   **不要为了"显得有创新"接入大模型**：与"本地优先、可解释、离线"的立项理由直接冲突，答辩必被问隐私、成本与不可复现。
-   **不要继续加功能模块**：模块数量已经不是短板，缺的是对已有模块的验证。
-   **不要在没有标注数据的情况下反复调权重**：调出来的权重无法解释，反而成为新的攻击点。
